# pic-click QA 交付记录

## 自动验证范围

- 数据：原图保持、标注 JSON 往返、说明保存、附件独立副本。
- 渲染：矩形、箭头、高亮、马赛克、序号、文字、文字卡、颜色卡。
- UI 冒烟：主窗口、标注贴图、说明窗口创建及退出。
- 交互集成：框选、Ctrl+T 贴图、编辑切换、矩形、撤销重做、原位多行文本、文字编辑取消、自由画笔、缩放、透明度、旋转、翻转、鼠标穿透恢复。
- 长截图：用户手动滚动、稳定帧检测、无重叠拒收、重复区域裁切、固定头部偏移、空输入保护和像素级结果比较；程序不再主动发送滚轮事件。
- 透明文字：Windows 透明色键输入层存在且可见，编辑控件使用同一透明色，输入、换行、修改、取消、撤销重做流程继续通过。
- 标注移动：文字命中、拖动坐标变换、选框跟随、持久化、撤销和重做；贴图模式的整窗拖动保持原行为。
- 客户保存设置：默认值、JSON 持久化、客户目录创建、编辑窗口入口、自动 PNG 生成及保存路径元数据。
- 云端上传：Windows DPAPI 凭据加密往返、中文路径 URL 编码、WebDAV 分级建目录和 PUT、Basic 鉴权、HTTP multipart POST、Bearer Token、用户标识头及返回链接解析。

## 已知风险

- 自动化执行环境无法提供真实交互桌面，真实屏幕捕获与系统集成必须人工验收。
- 旋转或翻转会把当前标注合并进图片，之后不能单独编辑旧标注。
- 鼠标穿透依赖 Windows 扩展窗口样式；安全桌面和受保护内容不保证可捕获。
- 当前记录目录无容量清理策略，大量截图与视频附件可能持续占用磁盘。
- 自动上传只针对截图创建时的版本；之后修改标注，应使用编辑工具栏或贴图右键菜单再次上传最新版本。

## 2026-09-13 手动滚动截图回归

- 缺陷：程序主动发送滚轮事件，但目标页面可能未接收，导致第二帧仍为第一页并被错误加入结果。
- 修复：移除自动滚轮事件，改为用户手动滚动；画面稳定后才采集，并要求新帧与上一帧通过重叠校验。
- 防错：没有可靠重叠的画面不会进入结果，控制窗提示用户向回滚动；支持手动捕获、完成、Esc 提前完成和取消。
- 回归断言：两次稳定观察后采集、无重叠拒收、四段重叠页面恢复为像素一致的完整长图、普通截图流程不受影响。
- 二次修复：动态页头曾使相同正文被识别成新帧，缩放取样还会产生约 1–3 像素接缝。现先比较页面主体，要求底部出现有效的新像素，再在原始纵向分辨率逐像素精修重叠位置；采集时保存已确认的裁切段，完成时不再重复计算。
- 新增断言：页头变化但正文不动时帧数保持为 1；向下滚动 240 像素时只追加 240 像素，并与原始长页面逐像素一致。
- 入口调整：移除主窗口及托盘的独立长截图按钮；普通框选松开后显示选区底部 Dock，由用户选择完成、滚动截图、复制、贴图或取消。桌面回归验证 Dock 出现后截图不会提前结束，并包含“滚动截图”入口。
- 焦点修复：滚动模式优先恢复截图前的前台顶层窗口，避免销毁遮罩后的短暂 DWM 窗口被误认成滚动目标。
- 宽页面精度：针对用户提供的 1743×1176 稀疏网页样例提高纵向采样精度和精修搜索范围；按 0/350/476 像素切成三个 700 像素视口后，裁切点为 350/574，恢复结果尺寸 1743×1176 且像素差为 0。自动测试中加入同尺寸稀疏卡片网页作为长期回归。
